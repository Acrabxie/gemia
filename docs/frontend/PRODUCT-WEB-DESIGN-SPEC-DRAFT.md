# Lumeri 产品前端与官网设计规范

**版本** v2.0 草案 0.4
**日期** 2026-08-05
**状态** 官网视觉方向、灰度重点层级与装饰克制原则已由 Acrab 拍板；产品布局章节仍是提案
**适用范围** Lumeri Video 桌面端、Web 工作区、iPad / iPhone 客户端，以及 `lumeri.io` 官网、支持页、隐私页与公开账号入口。
**不适用范围** 用户成片的视觉风格、镜头语言与剪辑风格；这些属于创作输出规范。

> 本草案用于建立下一版共同方向，不替换现行 [`DESIGN-SPEC.md`](./DESIGN-SPEC.md)。其中“公共 Web 使用安静的白 / 浅灰背景、以黑和灰度表示重点、Lumeri Video 蓝只作主入口与功能状态、圆角一体化表面、柔和阴影层次、无信息装饰直接删除”已获确认；未标记为已拍板的产品布局与跨端取舍仍需单独确认。

## 1. 一句话方向

**Lumeri 是一台精密而有体积感的数字创作设备：黑白构成主体，产品蓝只标记焦点与状态；官网由连续圆角表面组成，工作区让作品始终站在最前面。**

这个方向要求 Lumeri 的两个主要表面保持同一个品牌气质，但采用不同的信息密度：

| 表面 | 主要任务 | 视觉角色 | 默认密度 |
|---|---|---|---|
| 产品工作区 | 创作、判断、修改、交付 | 专业工作台 | 高，但必须清楚 |
| 官网 | 解释、证明、建立信任、引导行动 | 产品海报 / 编辑叙事 | 低，留白优先 |
| 支持与法律页 | 查找、理解、确认边界 | 安静文档 | 中，阅读优先 |

不把官网做成放大的 App，也不把 App 做成缩小的营销页。

## 2. 三个设计命题

### 2.1 视觉命题

**黑白、圆润、整体、真实，并具有可感知的空间层次。**

- 公共 Web 以白与浅中性灰为底，近黑承担主文字、产品容器和高优先动作。
- Lumeri Video 蓝只负责品牌识别、焦点、选中、滑轨与运行状态，不铺成大面积叙事色块。
- 背景保持纯白或单一浅灰；设计网格只用于内部对齐，不渲染为贯穿页面的纹理。
- 几何形状必须承载内容、动作、选择或表面层级；不承担语义的圆盘、短线、圆点和悬浮面不进入成品。
- 优先使用真实工作区、真实画面和真实创作结果；不以抽象 AI 光球、模型脑、数据粒子代替产品。
- 层级由尺寸、间距、明度、圆角接合、环境阴影与贴面高光共同建立；禁止零模糊彩色硬投影。
- 相关步骤优先进入同一个圆角轨道或整体表面；使用滑块表达选择，不把每个选项拆成独立彩色块。
- 官网第一屏必须让用户同时看见“Lumeri 是什么”和“Lumeri 实际长什么样”。

### 2.2 官网内容命题

官网首页只承担四件事：

1. **Hero：** 说清产品名、核心价值和一个主行动，并展示一个强产品画面。
2. **工作方式：** 用一个真实流程解释从描述到时间线的关系。
3. **产品深度：** 证明它不是聊天框，而是可查看、可干预、可继续编辑的创作工作区。
4. **最终行动：** 根据实际发布状态，引导登录、下载、查看源码或关注进展。

每一段只做一件事。若标题已经说明含义，正文不重复标题。

### 2.3 交互命题

动效只服务于三个感受：

- **进入：** 首屏中的品牌、承诺、动作和产品画面按阅读顺序出现。
- **理解：** 滚动时用一次轻量的空间变化，把用户从品牌叙事带进真实工作区。
- **确认：** hover、focus、展开和切换明确告诉用户“这里可以操作”，不制造装饰性运动。

产品端的编辑、拖动、裁剪和时间线操作以即时、稳定为先；官网可以更有氛围，但不能妨碍阅读和移动端性能。

## 3. 体验原则

### 3.1 作品优先

- 视频画面、时间线和创作结果永远比系统状态更醒目。
- 无内容时告诉用户下一步，有内容时让 UI 主动退后。
- 装饰元素不得与预览画面争夺最高对比度。

### 3.2 创作者可读

- 界面说“正在整理素材”“正在生成配音”，不说 provider、tool、job、runtime 或内部 ID。
- 后台工作按 Project 聚合；已完成任务自动退出主要视野，需要追溯时进入历史。
- 失败信息必须说明发生了什么、影响什么、下一步能做什么。

### 3.3 控制权可见

- 用户必须随时看见当前 Project、当前会话、执行状态和可停止入口。
- 需要用户决定时，Lumeri 应停下并给出有限、互斥、后果清楚的选项。
- 不用“自动”“智能”掩盖实际路由、权限或服务失败。

### 3.4 最少但不神秘

- 删除重复线索，不删除方向感。
- 图标适合高频工具；重要决策、不可逆动作和首次出现的能力保留文字。
- 一屏一个主动作；次要动作降为文字或低强调按钮。

### 3.5 状态必须诚实

- “源码完成”“已激活”“已在浏览器呈现”“已安装到设备”“已公开发布”是不同状态，界面和官网不得混写。
- 官网的“可用、测试中、建设中”必须来自可验证的当前发布状态。
- 无法确认的新鲜度或可用性时，使用中性描述，不使用确定性承诺。

## 4. 品牌系统

### 4.1 名称

- **Lumeri**：母品牌。
- **Lumeri Video**：视频创作产品。
- 官网品牌导航可使用 Lumeri；产品标题、下载、登录后工作区与 App Store 素材使用 Lumeri Video。
- 不在同一标题层级重复 “Lumeri / Lumeri Video / Lumeri AI Video Agent”。

### 4.2 标志

- 标志只使用正式矢量源，不重画、不加描边、不加投影、不放进额外圆形或方形底座。
- 数字界面建议最小高度 24px；与相邻文字和控件保持至少半个标志宽度的净空。
- 黑色表面使用白色标志，白色表面使用黑色标志；蓝色只可作为小面积激活版本，不为标志添加渐变、描边或装饰投影。
- 官网白色导航中的标志必须使用透明底；不得为了“按钮感”添加黑色圆角方块。
- 标志可以单独出现，也可以与 Lumeri 字标组合；不要与页面主标题争夺两个同等响亮的品牌层级。

### 4.3 核心色

| 角色 | 值 | 用途 |
|---|---|---|
| 公共 Web 主背景 | `#FFFFFF` | 官网、支持与法律页的主画布 |
| 公共 Web 次表面 | `#F4F5F7` | 连续区段、轨道与抬升面后的层次 |
| 核心强调 `fg-emphasis` | `#08090B` | 主文字、产品容器与高优先动作 |
| 重要 `fg-strong` | `#2D3036` | 次级标题、导航和未选中的重要对象 |
| 说明 `fg-body` | `#555B65` | 正文、解释和辅助操作 |
| 元信息 `fg-meta` | `#6F7580` | 编号、范围、低频标签与时间；白底对比度 4.63:1 |
| 非活跃 `fg-disabled` | `#A8ADB6` | 未激活箭头和弱提示；不得作为正文色 |
| 中间表面灰 | `#D9DDE3` | 轨道、接缝与立体层次 |
| Lumeri Video 主题蓝 | `#2F5BFF` | 焦点、选中、滑轨、状态光与小面积产品身份 |
| 主题蓝浅阶 | `#E7EDFF` | 焦点外围、轻提示与低强度蓝色表面 |
| App 主表面 | `#111415` | Lumeri Video 工作区背景；仍由产品规范管辖 |
| App 最深表面 | `#0B0F10` | 时间线井与最深舞台 |

规则：

- 公共 Web 的白、浅灰与黑约占 95%；主题蓝及其派生色合计不超过约 5%。
- 内容重要性必须由 `#08090B → #2D3036 → #555B65 → #6F7580 → #A8ADB6` 的灰度阶梯表达。转成灰度后，标题、正文、元信息和非活跃状态的层级仍须成立。
- 蓝色不能作为“这段内容更重要”的唯一线索；它只说明产品身份、键盘焦点、当前选择、可交互位置或运行状态。
- 唯一主入口（例如导航中的“登录”）可以使用蓝色实底；同一视口不得再叠加第二个无语义蓝色装饰面。
- 组件消费 `theme-accent` 角色，而不是写死“母品牌永远是蓝色”；切换到其他 Lumeri 产品时可替换主题色，不替换黑白骨架、圆角和高度关系。
- 常规产品 UI 与官网均禁止大面积装饰渐变。蓝色环境光只能辅助表达高度或状态，不能承担文字可读性。
- 红、黄、绿只表达错误、警告、成功；不参与品牌装饰。

### 4.4 表面关系

- App 采用明确的暗色明度阶梯：底层、贴边 chrome、内容模块、输入与浮层逐级变亮。
- 官网以大块连续圆角表面为主；相关选项共享一个外壳，分段优先用滑块、接缝、留白与明度，不堆叠独立卡片。
- 支持与法律页沿用公共 Web 的白底、黑字与蓝色焦点，提高正文行高，不使用营销型环境动效。
- 阴影只解释真实高度关系。静态装饰不得仅靠重阴影制造存在感，非交互元素不得添加 hover 漂移。

## 5. 排版

### 5.1 字体策略

- 中文优先使用系统中文字体；西文和数字使用系统 UI 字体。
- 全产品最多两个字体角色：正文 / UI 字体与等宽字体。
- 第一阶段不引入需要下载的新品牌字体，避免中文缺字、加载闪烁和跨平台差异。
- 文件名、时码、比例和调试型可复制值才使用等宽字体；普通正文不使用等宽字体制造“技术感”。

### 5.2 产品端

- 主要 UI 正文 14px；表单输入 16px；小型元信息 11–12px；标题按现行规范的 16 / 20 / 24px 档。
- 对话长文行高 1.6，Chrome 短标签行高 1.3–1.45。
- 中文阅读宽度建议 17–40em，上限 48em。

### 5.3 官网

- 品牌名是首屏最大文字；核心承诺必须低于品牌名一个层级。
- 桌面首屏品牌名建议使用 `clamp(80px, 10vw, 168px)`；移动端不得为了视觉冲击造成断字或横向滚动。
- 官网正文建议 16–20px、行高 1.7–1.9；说明文字不低于 14px。
- 大标题控制在 2–3 行内，正文通常只写一句。
- 中文与西文、数字之间保留合理空格；静态文案使用中文标点。

## 6. 产品布局

### 6.1 桌面与大屏

稳定骨架为：

`创作舞台 | 会话 | Projects`

- 创作舞台占剩余宽度，承担预览、时间线、大纲和后台任务等可重排模块。
- 会话栏基准宽度 400px；宽度变化必须重新验证中文行长、输入框和任务状态。
- Projects 栏基准宽度 240px，是 Project 与会话导航权威，不与素材库混合。
- 用户可以收起 Projects，但不应失去当前 Project 的可见身份。
- 模块可以调序和缩放，但视觉网格、最小尺寸和键盘替代路径必须稳定。

### 6.2 平板

- 横屏优先保留“创作舞台 + 会话”并排；Projects 进入可召回侧栏。
- 触控目标至少 44px，密集工具可保持小图标，但热区必须扩展。
- 时间线与预览不应同时被压缩成不可操作的缩略区；必要时允许单模块临时放大。
- iPad 外观与 DMG 使用同一信息架构、名称和输入逻辑，不另造一套“移动版产品”。

### 6.3 手机

手机布局尚未拍板。本草案推荐 **单工作面切换**：

- 顶部显示当前 Project / 会话与表面切换。
- 预览、时间线、会话、任务每次只把一个表面作为主工作面。
- 输入框固定在会话表面底部，不跨表面遮挡时间线。
- 后台任务以可召回状态条或任务表面出现，不长期占用狭窄主画面。

备选方案是“上预览 / 下会话或时间线”的纵向分屏。该方案能同时看见更多上下文，但在 390px 宽设备上会显著压缩编辑空间。需 Acrab 拍板后才能写成硬规则。

### 6.4 断点原则

- 使用内容驱动断点，基准仍沿用 600 / 840 / 1200 / 1600px。
- 320px 宽页面不得产生 body 横滚；时间线作为二维内容可在自身区域横向滚动。
- 响应式不是把桌面三栏等比缩小，而是按任务优先级折叠次级表面。

## 7. 产品信息架构

### 7.1 全局层级

1. 当前身份与账号状态。
2. 当前 Project。
3. 当前会话。
4. 当前创作工作区。
5. 素材库与可共享资产。
6. 设置、帮助与低频管理。

Project 内的会话应相对隔离；素材可以共享，但必须通过显式选择或交接进入会话上下文，不能因为“同一 Project”就自动污染上下文。

### 7.2 工作区模块

- **预览：** 当前作品或选中素材的真实结果。
- **时间线：** 可继续修改的结构，不是装饰性结果图。
- **大纲 / 计划：** 创作方向与关键决策，避免展示内部执行清单。
- **后台任务：** 当前 Project 内正在进行的工作；显示创作者能理解的目的和阶段。
- **会话：** 意图、解释、决策与控制入口。
- **素材库：** 共享资产及其明确来源，不自动进入会话上下文。

### 7.3 空态

- 标题说下一步，不说缺失事实。例如“导入媒体开始”，不用“暂无媒体”。
- 一行说明这里将出现什么。
- 只保留一个主动作；会话空态可提供 3–5 个可点击起手示例。
- 不做功能导览墙，不用多张卡片解释产品。

## 8. 官网结构

### 8.1 导航

建议保留：品牌、工作方式、产品状态、支持、登录与一个主 CTA。

- 桌面导航最多 5 个直接入口。
- 登录与主要获取动作不能同时都做成最高强调；根据当前发布阶段只选一个主 CTA。
- 移动端首屏至少保留品牌和主 CTA，其余入口进入菜单。

### 8.2 Hero

- Hero 必须铺满视口宽度，固定导航计入首屏高度预算。
- 顺序固定为：品牌名 → 核心承诺 → 一句解释 → 主动作 → 强产品视觉。
- 不使用统计条、Logo 墙、功能胶囊堆、悬浮 dashboard 卡片或多个并列 CTA。
- 推荐将真实工作区作为大面积裁切画面或空间背景，而不是放进厚重设备框。
- 若继续使用设备框，框只负责说明载体，不得比产品内容更醒目。

### 8.3 工作方式

用一个连续流程表达：

`描述想法 → Lumeri 规划并执行 → 在时间线上继续创作`

- 可以分三步，但不做三张 SaaS 卡片。
- 每一步只有一个动作标题和一句解释。
- 视觉上通过一条连续路径、滚动叙事或真实界面变化建立关系。

### 8.4 产品证明

- 至少展示一个未经营销重绘的真实工作区画面。
- 证明重点是“可看见、可干预、可继续编辑”，不是列举模型和工具数量。
- 产品截图周围的文案放在 HTML 中，不把营销标题烘焙进图片。
- 截图必须与当前发布版本相符；旧界面只能明确标记为历史或概念。

### 8.5 产品状态

- 状态表只呈现用户能采取行动的事实：可下载、测试中、等待开放。
- “本地优先”“不上传创作数据”等承诺必须与实际账号、设备和测试通道边界一致。
- 不披露内部端口、供应商、基础设施、任务 ID 或开发环境。

### 8.6 最终 CTA

根据发布阶段四选一：

1. 下载 Lumeri Video。
2. 登录 Lumeri。
3. 加入测试。
4. 查看公开源码 / 关注进展。

一个页面只设一个最高优先级选项。其他入口降为文字链接。

### 8.7 支持、隐私与账号页

- 与官网共用标志、颜色、导航和页脚，不共用营销动效。
- 页面标题、更新时间、适用范围和联系路径在首屏可见。
- 正文采用单列阅读布局；目录可在宽屏吸附，窄屏折叠。
- 账号页属于产品服务界面，使用产品端的表单、错误和焦点规则，不做官网式大标题表演。

## 9. 组件与状态

产品端的具体尺寸与控件仍以现行 [`DESIGN-SPEC.md`](./DESIGN-SPEC.md) 为准；公共 Web 新增以下已拍板的表面纪律：

- 卡片只有在“整块就是一个交互对象”时才成立；普通内容区优先用布局、分隔线和留白。
- 结构面只使用 `14 / 24 / 36 / 52px` 四档圆角；只有滑轨、状态点和圆形手柄使用全圆角。
- 浮层使用三档统一柔影和最多一层贴面高光来表达高度；不使用彩色硬偏移投影。
- 一组互斥选项优先组成一个连续轨道，选中滑块在轨道内移动；不得用三块不同主题色表达三个普通选项。
- 主要按钮一屏一个；次要动作使用 tonal、outlined 或 text 层级。
- 纯图标按钮必须有 `aria-label` / tooltip；不可逆动作保留明确文字。
- 成功默认静默；错误只在确实需要用户处理时使用红色。
- 运行中的同一对象只保留一个动效载体。
- 加载超过 10 秒才展示百分比与粗略时间；不能准确估时，不显示假精确倒计时。

## 10. Agent 与后台工作的呈现

- 会话先显示 Lumeri 正在完成的创作目的，再显示必要阶段。
- 后台任务按 Project 聚合，并标明是 Lumeri 主任务还是协作任务；不展示内部 agent 名称或编号。
- 完成项自动离开当前任务区；历史记录保留可追溯结果和时间。
- 工具调用默认折叠为人话结果，需要诊断时再进入技术详情。
- 需要用户选择时给出 2–4 个互斥选项、一个推荐项和每项后果。
- 用户停止任务后，界面立即确认停止请求，并区分“已停止”和“正在安全结束”。

## 11. 动效

### 11.1 官网建议动效

1. Hero 入口：品牌、承诺、动作与产品视觉在 600–800ms 内完成一次有序进入。
2. 流程选择：黑色选中滑块在三段圆角轨道中移动，真实产品画面同步切换；滑块与内容切换必须共享明确状态。
3. 产品深度：滚动驱动一次轻微的 scale / translate 变化，帮助用户进入工作区，不做无限视差。
4. 高度反馈：按钮按下、产品窗口抬升和卡面 hover 只改变 2–8px 位移、柔影与贴面高光，不弹跳、不漂浮。

### 11.2 产品端纪律

- 高频编辑不加过场动画。
- 状态变化优先 `transform` 和 `opacity`，避免连续动画尺寸属性。
- 进入使用减速，离开使用加速；可召回侧栏离开可以使用 standard 曲线。
- `prefers-reduced-motion` 下移除位移、缩放、呼吸和循环动效，信息仍须完整。
- 自动动效超过 5 秒必须可暂停，或改为静态表达。

## 12. 文案与语气

### 12.1 产品端

- 先写对象或动作：“导入媒体”“继续剪辑”“停止生成”。
- 状态写实际进展：“正在整理镜头”，不写“AI 正在施展魔法”。
- 错误写具体影响和下一步：“账号服务暂时不可用。你的本地 Project 未受影响，可稍后重试。”
- 不出现 LLM、模型路由、provider、runtime、tool、job、hash、session ID 等内部语言。

### 12.2 官网

- 标题承担意义，正文只补一个事实。
- 优先写创作结果、控制权和可继续编辑，不把“AI”作为每一段的主语。
- 避免“革命性、颠覆、全能、一键完成、永不失败、100%”等无法验证的宣称。
- 不把开发计划写成已发布能力。

### 12.3 推荐品牌句式

- 主价值候选：**把想法，直接放进时间线。**
- 产品解释候选：**描述你想完成的作品，Lumeri 会规划、执行，并把结果留在可继续编辑的工作区。**
- 品牌短句候选：**让创作只剩下想法。**

三者分别承担功能价值、产品解释和品牌情绪，禁止在同一屏全部重复出现。

## 13. 图像与产品画面

- 官网优先使用真实产品画面、真实成片帧和真实使用场景。
- 一个区段只放一个主视觉；需要多个时刻时，分成多个连续画面，不做拼贴海报。
- 截图裁切必须保留用户要理解的关系，例如会话与时间线，而不是只放局部按钮。
- 产品截图不叠加虚构数据、虚构成功率或不存在的功能。
- 不在截图内部烘焙网页标题、CTA 或段落；营销文案应可选择、可响应、可被辅助技术读取。
- 暂无高质量素材时，可使用纯色空间与真实产品裁切，不能用廉价抽象渐变填充叙事空缺。

## 14. 无障碍与性能底线

- 正文对比度至少 4.5:1；大文字至少 3:1；交互边界与焦点至少 3:1。
- 键盘焦点只用 `:focus-visible`，必须清楚可见，不得被固定导航遮挡。
- 主要触控目标至少 44×44px；所有指针目标满足 WCAG 2.2 最低要求。
- 所有图像有与用途相符的 alt；装饰图像使用空 alt。
- 官网首次视口不得因大图或字体加载发生明显布局跳动。
- Hero 主视觉应提供响应式尺寸和现代格式；移动端不下载桌面超大图。
- 页面主体不得横向滚动；二维编辑内容只能在自己的容器内滚动。
- 动效、视频与环境光效果不能成为理解内容的唯一方式。

## 15. 验收方式

### 15.1 产品界面

- 仅看标题、标签与状态，用户能否理解当前 Project、当前会话和当前工作？
- 真实任务运行时，目的、进度、停止入口和结果是否都可见？
- 隐藏内部 ID 后，创作者是否仍能准确判断发生了什么？
- 桌面、iPad 和手机是否保留同一信息架构，而不是三套产品？
- 键盘、触控、reduced-motion 和 320px reflow 是否通过？

### 15.2 官网

- 3 秒内能否看出品牌名、产品类型、核心价值和主动作？
- 第一屏是否有一个足够强的真实视觉锚点？
- 只扫标题能否理解全页逻辑？
- 每一段是否只承担一个任务？
- 删除阴影和装饰光后，构图是否仍然成立？
- 官网陈述是否与当前真实发布状态一致？

### 15.3 实施证据

规范落地不能只看源码或测试：

1. 源文件与 token 检查。
2. 实际服务或构建中的资源一致性。
3. 常用桌面与移动视口截图。
4. 键盘、触控和 reduced-motion 验证。
5. 浏览器控制台零新增错误。
6. Acrab 对关键画面的可见验收。

## 17. 已拍板与下一轮待确认

### 已拍板：公共 Web 视觉系统

- 黑白为主体，Lumeri Video 蓝只作点缀。
- 使用黑到灰的五级明度表示内容重点；蓝色不得承担内容优先级。
- 多用圆角与一体化组件；互斥流程采用滑动选择。
- 使用统一柔影、贴面高光与小幅位移建立立体层次。
- 允许其他 Lumeri 产品替换 `theme-accent`，不改变黑白骨架。

### 决策 1：官网第一视觉

- **A · 全幅真实工作区（推荐）：** 真实产品画面成为首屏空间，品牌文案落在安静区域；识别快、可信度高。
- **B · 电影化创作场景：** 以真实创作者 / 设备场景为主，产品画面后置；情绪更强，但需要新的高质量素材。
- **C · 保留当前设备框：** 改动最小、产品清楚，但更像常规 SaaS 展示。

### 决策 2：手机主布局

- **A · 单工作面切换（推荐）：** 可操作面积最大，适合手机。
- **B · 上下分屏：** 上下文同时可见，但预览、时间线和输入都更拥挤。

### 决策 3：官网最高优先 CTA

- 下载 Lumeri Video。
- 登录 Lumeri。
- 加入测试。
- 查看公开源码 / 关注进展。

应按真实发布阶段只选一个，不由设计稿擅自决定。

### 决策 4：视觉系统演进范围

- **A · 先统一品牌、官网和响应式规则（推荐）：** 不重写已稳定组件。
- **B · 同时重做产品组件视觉：** 一次性更统一，但范围大、验证成本高，也更容易破坏已确认交互。
